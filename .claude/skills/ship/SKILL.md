# Ship — 작업 조율

메인 채팅이 사용자 요청을 받아 조율한다. 역할은 특정 제품의 에이전트 유형이 아니라 아래 참조에 정의된 작업 계약이다. 실행할 담당의 참조만 필요한 시점에 읽는다.

이 프로젝트에서는 [팀 계약](../../../Docs/ProjectSkill/ChatRoles/README.md)을 먼저 읽고 원본 문서·승인·기록 경로를 확인한다. 호스트별 명령 인자 대신 실제 사용자 요청과 승인 범위를 기준으로 판단한다.

## 요청과 실행 경로

- 진행 조회·현재 확인 사항 질문: 로드맵·현재 Plan/WorkRecord·연결된 run만 읽어 상태·남은 확인·다음 후보를 보고한다. 새 실행이나 메시지를 보내지 않는다.
- 계획 요청: planner에게 계획만 맡긴다. 문서가 만들어졌다는 이유로 구현하지 않는다.
- 승인 범위 구현·검증 요청: 아래 순차 흐름을 사용한다.
- 특정 결함 재검증·리뷰 요청: 범위가 확정됐다면 필요한 담당부터 재개한다. 사용자 요구가 바뀌었을 때만 planner에게 설계 확인을 요청한다.

## 실행 환경 연결

1. 루트 AGENTS.md와 작업에 필요한 도메인 지침을 갖춘다. [실행 상태 계약](../../../.pipeline/README.md)에 따라 .pipeline/{run-id}/run.md를 생성하거나 같은 작업의 run을 재개한다. 조회만 할 때는 생성하지 않는다.
2. 요청·승인·대상 Plan·WorkRecord·기준 ID·버전·실제 도구/사용 담당을 연결한다. 명세·개발·QA 전문을 run에 복제하지 않는다.
3. 현재 호스트에서 독립 작업자를 생성·호출하고 완료를 기다리는 실제 기능이 있는지 확인한다. 역할명을 네이티브 에이전트 유형으로 가정하지 말고, 담당 참조·범위·입출력을 작업 지시로 전달한다. 도구 이름·호출 방식은 호스트가 제공하는 기능에 맞춘다.
4. 실제 작업자 식별자와 독립 실행 여부를 기록한다. 사용자가 지정하지 않은 모델·인증·MCP 서버·설정은 새로 만들지 않는다.
5. 독립 위임 기능이 없으면 제한과 수동 전달 문안을 보고한다. 같은 대화의 역할극을 독립 테스트·리뷰로 표시하지 않는다. 별도 기존 채팅에 메시지를 보낼 때는 인간 사용자의 직접 승인·대상 확인이 필요하다.

문서의 역할 제한은 작업 계약이며 보안 샌드박스나 도구 차단 설정이 아니다. 하위 작업자는 스스로 재위임하지 않고 메인 채팅으로 결과를 반환한다. 스킬 설치·설정 변경 요청만으로 이 파이프라인의 실제 구현·검증이 승인되지는 않는다.

## 순차 실행

| 담당 | 전달할 최소 자료 | 다음으로 넘길 조건 |
| --- | --- | --- |
| [planner](references/planner.md) | 요청·승인 범위·기존 Plan·관련 기획/현황 링크 | 미결정·범위 충돌이 없고 실제 구현 승인이 확인됨 |
| [coder](references/coder.md) | 승인 Plan·요구/결함 ID·run/WorkRecord·편집 범위 | 실제 변경·기본 검증·버전·실행 환경 사용 종료가 기록됨 |
| [tester](references/tester.md) | 같은 Plan·변경 버전·개발 근거·시험 범위 | 기준별 결과·재현·미실시·사용자 확인이 기록됨 |
| [reviewer](references/reviewer.md) | 요청·Plan·실제 변경·개발/QA 근거·버전 | 판정·관련 ID·사유·다음 담당이 기록됨 |

기존 승인 Plan이 있으면 planner는 필요한 범위 확인만 하며 불필요한 재설계를 하지 않는다. 앞 담당의 실제 종료와 산출물 내용을 확인한 뒤 다음 담당을 호출한다. 파일 생성·호출 접수는 완료가 아니다. 메인 채팅은 원문 링크와 담당자의 짧은 결과만 유지한다. 같은 Maker·공유 체크아웃·문서의 편집과 실행 검사는 병렬 사용하지 않는다.

## 수정·대기·종료

- CHANGES_REQUIRED이면 같은 승인 범위에서 coder → tester → reviewer로 수정 회차를 진행한다. 기획 변경이 필요하면 사용자에게 질문한다.
- 필수 환경/도구가 없으면 WAITING_ENV, 사용자 직접 확인·미결정이 남으면 WAITING_USER로 둔다. 미실시를 통과시키지 않는다.
- 동일 원인의 수정 후 재검증이 두 번 연속 실패하면 추가 자동 재시도 대신 현재 근거·선택지를 보고한다. 범위·비용·위험이 커지면 그전이라도 사용자에게 판단을 요청한다.
- READY라도 사용자 단계 판단을 대신하지 않는다. 현재 run의 완료 기준이 충족된 범위만 결과를 Features에 정리하고 남은 ID는 Plans에 유지한다.
- 원본 이관·추적·링크 정리가 끝난 완료 Plan/WorkRecord/run만 정리한다. 현재 상태와 무관한 다음 로드맵 단계를 자동 시작하지 않는다.
- 문서·검토 요청으로 제품 수정·commit·push·배포·채팅 생성/전송 권한을 확대하지 않는다.

## 사용자 보고

현재 단계/대상 버전, 역할별 실제 수행, 구현·테스트·리뷰 결과, 남은 사용자 확인, 다음 담당을 짧게 보고한다. 문서만 확인했으면 새 Play/QA 결과로 쓰지 않는다.

상시 감시·정기 알림·자동 후속 실행은 기본 동작이 아니다. 사용자 요청과 해당 호스트가 지원하는 예약/대기 도구가 있을 때만 설정한다.

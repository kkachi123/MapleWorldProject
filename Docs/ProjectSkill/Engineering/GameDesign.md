# Project StayCool — 게임 기획

> Infinity Blade를 오마주한 4방향 입력 기반의 반응속도 사이드뷰 대치 전투와, 방 카드 선택형 던전 탐험을 결합한 로그라이트. 패배해도 메소와 영구 강화는 유지되며 재도전마다 플레이어가 성장한다.

이 문서는 만들고자 하는 게임의 목표 기획이다. 구현 완료 여부를 나타내지 않는다. UI의 확정 사항과 협의할 세부 배치는 구분한다.

## 1. 기본 방향

| 항목 | 내용 |
| --- | --- |
| 전투 | 플레이어 1명과 상대 몬스터 1개체의 1:1 대결. 적 패턴에 맞춰 뒤 회피·가드·앞 회피·공격으로 대응 |
| 플레이 환경 | PC·모바일 가로 화면 공통 |
| 플레이 인원 | 1인 전용. 다른 플레이어는 한 판의 전투·진행에 관여하지 않음 |
| 조작 | 방향키 또는 화면의 하단 십자형 버튼. 두 입력의 동작·표시 상태를 동기화 |
| 탐험 선택 | 방 카드 3장 중 1장 선택 |
| 한 판 구성 | 탐험 3회 → 상점 → 중간보스 → 탐험 3회 → 상점 → 최종보스, 총 10 Stage |
| 반복 성장 | 메소·영구 강화 유지, 레벨에 따른 스킬 포인트 획득 |
| 스킬 구성 | 공격 버튼에 사용할 액티브 스킬 1개 + 패시브 스킬 3개 |

## 2. 용어

| 용어 | 의미 |
| --- | --- |
| 마을 | 몬스터·보스·NPC와 난이도를 결정하는 던전 테마 |
| 한 판(Run) | 선택한 마을의 던전에 입장해 최종보스를 처치하거나 사망할 때까지의 도전 |
| Stage | 한 판을 구성하는 방 하나. 상점·중간보스·최종보스도 각각 1 Stage로 계산 |
| 탐험 Stage | 전투·보물·안식처 카드 중 하나를 선택해 진행하는 방 |
| 임시 요소 | 레드 메소·상점 장비·상점 소비아이템·임시 강화. 한 판이 끝나거나 사망하면 소멸 |

## 3. Core Loop

```text
시작 화면
  ├─ 대장간: 장비 제작·강화
  ├─ 스킬 강화: 스킬 포인트 사용
  └─ 프로필: 플레이어 정보·장비·액티브 1개 / 패시브 3개 설정
      ↓
마을 선택 → 던전 입장
      ↓
탐험 3회 → 상점 → 중간보스 → 탐험 3회 → 상점 → 최종보스
      ↓                                            ↓
도중 사망 → 실패 결과                      최종보스 처치 → 성공 결과
      └──────────────── 한 판 결과 확인·메소 등 정산 ────────┘
                             ↓
                         시작 화면
```

### Stage 순서

| 순서 | 방 | 진행 방식 |
| --- | --- | --- |
| 1~3 | 탐험 | 매번 방 카드 3장을 제시하고 1장 선택 |
| 4 | 상점 | 다음 방 선택 대신 고정 상점 입장 |
| 5 | 중간보스 | 중간보스전 |
| 6~8 | 탐험 | 매번 방 카드 3장을 제시하고 1장 선택 |
| 9 | 상점 | 다음 방 선택 대신 고정 상점 입장 |
| 10 | 최종보스 | 처치하면 한 판 성공 |

- 무작위 카드 후보는 전투·보물·안식처 3종이다. 상점은 무작위 후보에 포함하지 않는다.
- 한 번 제시되는 카드 3장 안에서 같은 종류는 0~2장까지 등장할 수 있다. 예: 전투·전투·안식처.
- 전투 승리 또는 보물·안식처 이용 완료 후 다음 Stage로 진행한다. 사망하면 남은 Stage와 관계없이 실패 결과로 이동한다.

### 방 진입과 화면 전환

방 선택 → 화면을 검게 가림(암전) → 방 준비·플레이어 배치 → 화면을 밝힘 → 해당 방 UI 표시 순으로 진행한다. 전투 진입 시 플레이어는 암전 중 `BattlePos2`에 배치하며, 입장용 걷기 연출은 사용하지 않는다.

전투 승리 후에도 암전으로 다음 방 선택 또는 고정 상점·보스 입장을 연결한다. Fade In/Out이라는 명칭 대신 화면이 가려지는지·밝아지는지를 기준으로 전환을 정의한다.

## 4. 조작과 전투

### 4.1 입력과 위치

| 입력 | 동작 | 위치·표시 |
| --- | --- | --- |
| ↑ / 위 버튼 | 선택한 액티브 스킬로 공격 | 공격 모션, 적 HP 감소 |
| ↓ / 아래 버튼 | 가드 | 가드 모션 |
| ← / 왼쪽 버튼 | 뒤 회피 | `BattlePos1`로 이동 |
| → / 오른쪽 버튼 | 앞 회피 | `BattlePos3`로 이동 |

- 기본 대기 위치는 중앙의 `BattlePos2`다.
- 전투 중 앞·뒤 이동은 순간이동이 아니라 걷기 애니메이션과 위치 보간을 사용한다. 전투 진입 시의 즉시 배치와 구분한다.
- 먼저 수락한 한 동작만 실행한다. 동작 중 다른 동작 입력은 무시하며 입력 예약·동작 취소를 추가하지 않는다.
- 같은 가드·회피 동작의 키보드·WASD 별칭·UI 홀드를 출처별로 합산하고 마지막 입력이 해제될 때 종료한다. 공격은 ↑/W 또는 기존 공격 버튼으로만 실행한다.
- 이동 도중 마지막 방향 홀드가 해제되면 현재 위치에서 중앙으로 복귀하기 시작한다. 복귀 완료까지 새 동작은 무시하며, 완료 후 다시 입력해야 한다.

### 4.2 적 공격과 대응

전투는 **플레이어 1명 대 현재 상대 몬스터 1개체의 1:1 대결**이다. 적 공격은 대응 유형(뒤 회피형·앞 회피형·방향 무관 회피형·가드형)과 속성(일반·특수·패링)을 조합한 텔레그래프로 예고한다. 아래 규칙은 2026-10-20 사용자 선택·직접 답변으로 확정했으며 구현 완료를 뜻하지 않는다. 구현 범위·판정 경계는 [2단계 CombatCore](Plans/2_CombatCore.md)를 따른다.

| 공격 속성 | 대응·피해 |
| --- | --- |
| 일반 | 예고된 방향 회피 또는 가드 홀드. 범위 밖이면 피해 0, 가드면 원래 피해의 40%. 유효한 방향 저스트 회피는 슬로우 성공. 짧은 가드에도 패링 그로기는 없음 |
| 특수 | 가드·패링 불가. 예고 방향으로 피격 범위를 벗어나며 유효한 저스트 회피는 슬로우 성공. 특수+가드형 예고 조합은 사용하지 않음. 범위 안에서 가드하면 원래 피해를 받고 결과 문구는 "가드 불가"로 표시(2026-11-03 사용자 결정, 규칙·수치 불변) |
| 패링 | 예고 방향 저스트 회피 또는 정확한 ↓ 패링 성공이면 피해 0. 실패한 가드 홀드는 원래 피해의 40%, 범위 안 회피 실패는 원래 피해. 가드형 예고는 ↓ 패링만 저스트 성공으로 인정 |

- 대응 유형별 범위(2026-11-03 사용자 결정): 뒤 회피형·앞 회피형은 2칸을 공격한다. 방향 무관 회피형은 예고 시작 순간 1칸을 고정해 공격하며 이후 추적하지 않는다. 칸을 고르는 방식은 두 가지다. 하나는 플레이어와 가장 가까운 칸이고, 다른 하나는 1~3번 칸 중 무작위 칸이다(무작위는 2026-11-03 사용자 결정, 플레이어 위치 무관). 그 칸을 벗어나면 피해 0이고, 고정 칸에서 멀어지는 방향이면 어느 쪽이든 저스트 회피로 인정한다. 끝 칸은 벽 때문에 중앙 쪽 한 방향만 가능하다. 1칸 공격도 위 속성 규칙을 그대로 따른다. 3칸 전체를 치는 가드형은 여러 칸을 공격하는 보스용으로 두며 머쉬맘은 사용하지 않는다.
- 현재 전투 상대(2026-11-03 사용자 설명): 지금까지 "주황버섯"이라고 부른 현재 상대는 1번 마을(헤네시스)의 최종보스 **머쉬맘**을 뜻한다. 아래 공격 구성·착지 결정은 머쉬맘 기준이다. 현재 구현은 아직 주황버섯 리소스(주황버섯 모델·OrangeMushroomAttack 스크립트)를 쓴다. 실제 머쉬맘 리소스 교체와 이름 변경은 [2단계 Plan §18](Plans/2_CombatCore.md)의 다음 회차 후보다. 일반 몬스터 주황버섯은 §5대로 따로 남는다.
- 패턴 데이터는 맞히는 칸(칸 선택 방식 포함)·대응 유형·속성·예고·출현 가중치를 정한다. 가중치 기본값은 모두 같고 몬스터마다 조절한다. 그 범위를 어떤 모션·이펙트로 보여 줄지는 몬스터마다 정한다. 머쉬맘은 2칸 공격에서 두 칸의 중간에 착지한다. 다른 보스는 칸마다 이펙트를 따로 낼 수 있다(예: 팔 2개).
- 머쉬맘 공격 구성(2026-11-03 사용자 결정, 보라 세 가지 사이 비중만 planner 기본안): 머쉬맘은 가장 낮은 난이도인 1번 마을(헤네시스)의 최종보스이며 점프 공격만 쓴다. 보라(패링) 2칸 좌·우, 보라 1칸(가장 가까운 칸), 특수 1칸(무작위 칸)의 네 가지다. 특수 출현 비중 약 1/7은 사용자 결정이다. 보라 세 가지가 나머지를 같게 나누는 비중(2:2:2, 각 2/7)은 사용자가 따로 정하지 않아 planner가 정한 기본안이며([Plan §17](Plans/2_CombatCore.md)), 사용자 V11에서 체감을 확인한다. 일반 속성 공격과 2칸 특수 공격은 쓰지 않는다. 일반 속성 규칙은 이후 몬스터를 위해 유지한다.
- 실제 공격 시점의 위치·수락 입력으로 판정한다. 실제 범위 밖에 있으면 잘못된 버튼을 이유로 피해를 만들지 않으며, 성공 보상은 해당 예고와 맞는 입력에만 준다.
- 저스트 회피·패링은 실제 공격 시점 직전 **0.20초** 안에 시작한 입력을 인정한다. 유효 성공 피해는 0, 일반 가드 경감은 **60%(잔여 피해 40%)**다. 판정 수치·피해/경감은 DataSet에서 조절한다.
- 저스트 회피·패링 성공만으로 자동 공격하지 않는다. 성공 후 **2.0초** 안의 **다음 직접 공격 1회 전체 타격에 ×2.2**를 적용한다. ↑/W·기존 위 버튼을 사용하며 별도 반격 버튼·동작은 추가하지 않는다.
- 반격 보너스는 유효 시전 시작에 소비해 빗나가도 소모한다. 거부 입력·시전 실패는 소비하지 않고 진행 중 공격에는 소급 적용하지 않는다. 재성공은 중첩 없이 2.0초를 갱신한다.
- 저스트 회피는 **현재 대결 상대 1개체**의 행동·모션 진행을 **2.0초 동안 ×0.5**로 늦춘다. 패링은 그 상대를 **1.5초 그로기**로 만들고 어지러움 애니메이션을 표시한다. 현재 어지러움 모션은 상대 몬스터에 이미 설정된 hit 애니메이션을 재사용한다(2026-11-02 사용자 결정, 전용 자원 없음). 플레이어·팝업/토스트·오디오는 늦추지 않는다.
- 슬로우·그로기·반격 창은 정지 가능한 전투 시간으로 잰다. 동일 효과는 중첩 없이 갱신한다. 패링 성공 시 현재 공격의 미실행 타격을 취소하고, 처음 위치로 복귀를 마친 뒤 그로기를 시작한다(2026-11-02 사용자 변경, 반격 창은 성공 시점부터). 둘이 겹치면 그로기가 행동을 막고 슬로우 남은 시간은 흐른다. 사망·이탈·종료·상대 참조 폐기 시 이전 효과를 제거한다.
- 현재 상대 참조의 단일 소유권을 사용한다. 비전투 몬스터·다른 플레이어의 상대에게 공격·효과를 확산하지 않으며 다중 대상 전투 체계를 만들지 않는다.
- 저스트 회피·패링 판정은 이후 스킬·스탯으로 보정할 수 있는 경계를 둔다. 성장 시스템 자체는 이후 단계에서 연결한다.
- 적 HP가 0이면 해당 전투에서 승리한다. 적은 die 모습으로 멈춘 뒤 화면 암전(fade)을 거쳐 다음 Stage로 넘어간다(2026-11-03 사용자 결정). die 유지는 2단계에서 맞추고 암전·Stage 전환은 4단계에서 연결한다. 플레이어 HP가 0이면 한 판이 종료된다. 승패·동시 전투 불능 우선순위·정산 구현은 3단계 범위다.

### 4.3 팝업 중 전투 일시정지

- 전투 중 팝업은 서버의 일시정지 승인 후 표시한다. 요청 대기부터 새 전투 입력을 차단한다.
- 팝업이 열리면 전투의 이동·공격·피해·AI·판정 시간·스턴과 전투 연출을 모두 정지한다. BGM·효과음과 팝업·토스트 UI는 계속 동작한다.
- 닫으면 진행 중 공격은 남은 실행부터 재개한다. 가드·회피 홀드는 해제하고 회피는 중앙으로 복귀시킨다. 정지 중 입력은 예약하지 않으며 재개 후 새로 입력해야 한다.
- 사망·맵 이탈·종료는 재개보다 우선하며 이전 전투를 복원하지 않는다.
- 현재 맵의 구현·Maker 검증 근거는 [CombatPause 개발문서](Features/0_CombatPause.md), 실제 맵 전환·기기별 화면·음향의 남은 확인은 [후속 검증 계획](Plans/CombatPause.md)에서 관리한다. 목표 기획과 확인한 환경의 범위를 구분한다.

## 5. 마을과 몬스터

마을마다 테마에 맞는 일반 몬스터 최소 2종류, 중간보스 1마리, 최종보스 1마리를 구성한다. 일반 몬스터 최소 2종류는 마을의 콘텐츠 종류 수다. 각 전투의 현재 상대는 그중 1개체로 고정하며 동시에 여러 몬스터와 대결하지 않는다.

마을별 난이도는 단계적으로 높아지고 순차 해금된다. 구체적인 해금 조건과 방별 상대 종류·보스 배정은 추가 확정한다. 상대 1개체 고정 규칙은 유지한다.

마을 순서는 "1번 마을(헤네시스)"처럼 적는다. 개발 로드맵의 "단계"와 섞지 않기 위해서다.

| 1번 마을(헤네시스) | 콘텐츠 |
| --- | --- |
| 일반 몬스터 | 주황버섯·초록버섯. 추가할 때 공격 구성을 사용자에게 확인한다 |
| 최종보스 | 머쉬맘(Stage 10, 2026-11-03 사용자 결정). 현재 2단계 전투 상대이며, 구현은 아직 주황버섯 리소스를 쓴다(§4.2) |
| 중간보스 | 미정 |
| NPC | 리나·마야·밍밍부인 등 |

상점·보물·안식처에서는 마을 NPC를 배경에 배치하고 대화와 상황별 선택지를 제공한다. 보상 희귀도는 일반 몬스터 → 중간보스 → 최종보스 순으로 높아지며, 난이도가 높아질수록 더 희귀한 아이템을 획득할 수 있다.

## 6. 방 종류와 보상

| 방 | 내용 | 보상·재화 |
| --- | --- | --- |
| 전투 | 해당 마을의 일반 몬스터와 전투 | 처치 시 메소·장비 재료·소비아이템 중 하나 드롭. 상대 몬스터의 처치 경험치는 해당 전투 종료 후 정산 |
| 보물 | 일정 범위 안에서 무작위 보상 획득 | 메소·레드 메소 또는 한 판 한정 능력치·스킬 강화 |
| 상점 | 중간보스·최종보스 직전 고정 등장 | 레드 메소로 한 판 한정 장비·소비아이템 구매 |
| 안식처 | 체력 회복 | 회복량·조건은 추가 확정 |

보스는 특정 장비를 드롭한다. 일반 드롭과 보스 장비의 구체적인 목록·수량·확률은 별도로 정한다.

### 영구 성장과 한 판 한정 성장

- **메소·영구 강화:** 사망해도 유지된다. 메소는 대장간의 무기·방어구·장신구 제작과 강화에 사용한다.
- **장비 강화:** 스타포스와 잠재능력 강화를 포함한다. 비용·성공 규칙·단계는 추가 확정한다.
- **스킬 강화:** 플레이어 레벨에 따라 스킬 포인트를 지급하고 스킬을 강화한다.
- **한 판 한정 요소:** 레드 메소·상점 장비·상점 소비아이템·임시 능력치/스킬 강화는 방 사이에서 유지되며, 한 판 종료 또는 사망 시 소멸한다.
- **경험치 정산:** 각 전투 종료 후 경험치를 정산하고 Level·EXP를 갱신한다. 전투 중에는 처치 경험치를 즉시 반영하지 않는다.
- **한 판 결과:** 경험치 획득 내역을 표시하고 메소·아이템 등 나머지 보상을 정산한다. 이미 정산한 경험치는 중복 지급하지 않는다. 실패 시 지급 범위와 일반 드롭·제작 장비의 유지 규칙은 추가 확정한다.

## 7. UI 구성

### 7.1 확정한 공통 방향

- PC·모바일 가로 화면을 함께 지원한다. PC는 방향키·마우스, 모바일은 터치로 같은 동작을 수행한다.
- 전투 조작은 하단 십자형 4버튼이다. ↑ 공격, ↓ 가드, ← 뒤 회피, → 앞 회피 배치를 유지한다.
- 방 선택은 연결 노드맵 대신 카드 3장 중 1장을 선택하는 팝업이다.
- 키보드 입력도 해당 UI 버튼에 표시한다. 홀드 상태·동작 중 상태가 서로 어긋나지 않도록 한다.

아래 화면별 요소와 세부 배치는 **협의 초안**이다. 원문에 있는 기능을 화면에 배치한 것이며, 최종 크기·아트·텔레그래프 표현 방식은 함께 조정한다.

### 7.2 화면 목록과 이동

| 화면 | 주요 정보·조작 | 연결 |
| --- | --- | --- |
| 시작 화면 | 보유 메소, 플레이어 레벨, 던전 시작, 대장간, 스킬 강화, 프로필 | 마을 선택 또는 성장 메뉴 |
| 마을 선택 | 마을 이름·테마·난이도·해금 상태, 입장 | 선택한 마을의 첫 방 카드 |
| 프로필·스킬 설정 | 플레이어 정보·장비, 액티브 1슬롯·패시브 3슬롯, 스킬 설명·교체 | 시작 화면 |
| 대장간 | 무기·방어구·장신구 목록, 제작 재료·메소, 스타포스·잠재능력 강화 | 시작 화면 |
| 스킬 강화 | 보유 스킬 포인트, 스킬 레벨·효과, 강화 비용·전후 비교 | 시작 화면 |
| 방 선택 | 현재 마을·진행도, 전투·보물·안식처 카드 3장, 현재 HP·레드 메소 | 선택한 방 |
| 전투 HUD | 플레이어·적 HP, Level·EXP, Stage 진행도, 공격 예고, 반격 상태, 십자형 조작 버튼 | 승리 후 다음 Stage / 사망 시 결과 |
| 보물·안식처 | NPC·대화·선택지, 획득 보상 또는 회복 결과 | 다음 Stage |
| 상점 | NPC·대화, 보유 레드 메소, 상품·가격·효과, 구매, 다음 보스 진입 | 중간보스 또는 최종보스 |
| 결과 화면 | 성공·실패, 도달 Stage, 처치 기록, 경험치 획득 내역, 메소·아이템 정산, 임시 요소 소멸 안내 | 시작 화면 |

### 7.3 시작 화면·성장 메뉴 초안

시작 화면은 플레이어와 마을 테마를 중심으로 구성하고, 보유 메소·레벨과 던전 시작 버튼을 우선 표시한다. 대장간·스킬 강화·프로필은 시작 화면에서 여는 별도 메뉴로 구성한다.

프로필에서는 액티브 1개와 패시브 3개를 명확하게 구분한다. 대장간에서는 영구 성장에 사용하는 메소·재료를, 던전 상점에서는 레드 메소와 한 판 한정 상품을 구분해 표시한다.

### 7.4 전투 화면 초안

```text
┌──────────────────────────────────────────────────────────┐
│ 시스템 UI 여백     마을명 · Stage n/10      시스템 UI 여백 │
│       플레이어 HP                         적 이름·HP     │
│                                                          │
│       플레이어          대치 공간          몬스터        │
│                                 판정 결과·반격 상태      │
│                                                          │
│                           [↑ 공격]                        │
│ 레드 메소        [← 뒤 회피]      [→ 앞 회피]   패시브 3개    │
│                           [↓ 가드]                        │
│                  Level + exp (메이플 Layout)              │
└──────────────────────────────────────────────────────────┘
```

- 위 공격 버튼에는 선택한 액티브 스킬의 아이콘을 사용한다. 별도의 다섯 번째 공격 버튼은 추가하지 않는다.
- 화면 하단에 메이플식 Level·EXP 표시를 둔다. 전투 중에는 정산 전 값을 유지하고, 전투 종료 후 경험치 정산 결과를 반영한다.
- 판정 피드백은 몬스터 동작을 가리지 않는 위치에 둔다. 공격 예고 문구는 표시하지 않는다. 맞는 BattlePos 칸만 예고 시작부터 판정까지 반투명 속성색으로 표시한다(일반 노랑·특수 적색·패링 보라). 대응 방향은 칸 위치로, 속성은 칸 색으로 구별한다(칸 표시 2026-11-02, 문구 제거·속성색 2026-11-03 사용자 결정, 판정 불변).
- 판정 결과·상태 문구(저스트 회피 성공·패링 성공·가드·피해 경감·회피·피격·반격 준비·상대 그로기/슬로우)는 유지한다. 특수 공격을 범위 안에서 가드하면 결과 문구를 "가드 불가"로 표시한다(2026-11-03 사용자 결정).
- 저스트 회피·패링 성공·반격 가능 상태를 짧고 구별되는 피드백으로 표시한다. 패링 성공은 머리 위 별 표시를 키우고 위치를 조정하며, 패링 순간에는 접촉 지점에 네이티브 파티클 강조를 한 번 더한다. HUD 문구는 확대·강조하지 않는다(2026-11-02 사용자 결정). 정확한 판정 시간의 수치 노출 여부는 미정이다.
- 패시브 3개는 장착 상태를 확인하는 작은 표시로 두며, 전투 중 교체 가능 여부는 별도 결정한다.

### 7.5 방 카드·이벤트 화면 초안

방 선택 팝업 상단에는 마을과 다음 Stage를, 중앙에는 카드 3장을 가로로 배치한다. 각 카드에는 방 유형 아이콘·이름·짧은 설명을 표시하며, 현재 HP와 레드 메소를 함께 보여 선택을 돕는다.

카드 하나를 선택하면 중복 선택을 막고 방 전환으로 이어진다. 4·9번째 Stage에서는 카드 선택 없이 상점으로 이동하고, 상점에서는 다음 상대가 중간보스인지 최종보스인지 표시한다.

보물·안식처·상점은 NPC 대화와 선택지 영역을 공통된 형태로 구성한다. 보물은 실제 획득 결과를, 안식처는 회복량과 회복 후 HP를, 상점은 가격·상품 효과와 구매 결과를 표시한다. 원문에 없는 추가 보상 선택 규칙은 도입하지 않는다.

### 7.6 화면 전환·가독성 기준

- 1920×1080 기준으로 구성하고 화면 가장자리는 앵커를 사용한다. 모바일 노치·홈 영역을 피하도록 안전 영역을 둔다.
- PC의 좌상단 채팅·우상단 시스템 메뉴 영역과 겹치지 않게 주요 정보를 배치한다.
- 터치 대상은 최소 88×88px, 인접 버튼 간격은 최소 16px를 기준으로 잡고 실제 기기에서 확인한다.
- 전투 장면과 적의 공격 모션을 우선 보여준다. 상세 장비·스킬 설명은 메뉴에서 제공한다.
- 방 선택·상점·결과 화면과 암전 중에는 뒤의 전투 입력을 차단한다. 키보드와 터치 모두 같은 차단 상태를 따른다.
- 색상뿐 아니라 아이콘·문구로도 재화와 상태를 구분한다. 메소와 레드 메소, 유지되는 보상과 사라지는 임시 요소를 혼동하지 않게 한다.

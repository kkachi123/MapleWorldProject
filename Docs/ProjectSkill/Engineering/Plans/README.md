# Plans — 이 프로젝트의 제작 계획

앞으로 할 일·승인 범위·완료 기준을 관리한다. 팀 책임·인계·권한은 [ChatRoles 운영 규칙](../../ChatRoles/README.md), 계획서 자체의 내용·양식은 [공통 Plan 작성 원칙](../../Plan_Writing_Guide.md)을 따른다.

## 위치·내용

- 단계별 파일: {단계번호}_{FeatureKey}.md. 번호는 로드맵과 맞춘다.
- 단계 없는 요소·후속 확인: {FeatureKey}.md.
- 수정·리팩토링 단기 계획: Engineering/{TaskName}Plan.md. 작은 변경은 기존 계획의 항목으로 관리할 수 있다.
- 의도·확정 요구·제안/미결정·포함/제외 범위·필수 경계·실행 단계·AI/사용자 확인 기준을 담는다.
- 현재 동작은 [Features](../Features/README.md), 상세 실행·실패·검증·인계는 [WorkRecords](../WorkRecords/README.md)로 연결한다.

## 편집·진행

- 기획: 요구·승인 상태·설계·기준. 개발: 구현 상태·다음 행동. QA: 확인 상태·남은 조건.
- 같은 파일은 순차 편집한다. 개발/QA가 요구를 변경해야 하면 기획·사용자 판단으로 돌린다.
- 미착수 / 구현 후 확인 대기 / 해당 범위 완료 / 보류를 구분하고 자동 검사와 사용자 직접 확인을 별도 표시한다.
- 후속 항목은 고유 ID·미실시 상태·실행 시점·기준을 유지한다. 계획 작성만으로 구현·테스트 승인을 간주하지 않는다.

## 완료·삭제

결과를 Features에 반영하고 필요한 미완료 추적·링크를 정리한 뒤 완료 계획만 삭제한다. 미확인·보류가 남으면 유지하거나 사용자 승인으로 후속 계획에 분리한다. 상세 작업 기록의 이관·삭제는 팀 운영 규칙을 따른다.

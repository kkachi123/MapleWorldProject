## 1. 목표·승인 상태

공격 예고에 맞춰 가드·방향 회피·저스트 회피·패링을 판정하고, 성공 뒤 사용자가 직접 공격해 증가한 피해를 주는 전투를 만든다. 슬로우·그로기·피해 숫자와 실제 판정이 일치하며 모든 판정 수치를 DataSet에서 조절한다.

사용자는 2026-10-20 “v08 확인완료. 다음 단계 진행해줘.”라고 보고했다. 1단계는 종료했고 **2단계 진행은 승인된 상태**다. 같은 날 Q1~Q4의 A 선택과 “상대 몬스터는 1개체 고정(1:1대결)” 직접 답변으로 D01~D04를 확정했다. GameDesign·로드맵·본 Plan을 동기화했으며 같은 진행 승인 범위에서 coder에게 인계할 수 있다. 추가 규칙 질문이나 단순 구현 허락을 다시 요구하지 않는다.

## 2. 확정 요구·범위

사용자 확정: 1인 전용·플레이어 1명 대 현재 상대 몬스터 1개체의 1:1 대결·PC/모바일 가로 화면, 하단 십자형 네 입력, 먼저 수락한 한 동작만 실행, 입력 예약·동작 취소 없음, 동일 홀드의 출처 합산과 중앙 복귀 잠금을 유지한다. 공격은 ↑/W·기존 위 버튼이며 별도 반격 버튼·자동 반격은 사용하지 않는다.

포함:
- 대응 유형(뒤 회피·가드·앞 회피)과 속성(일반·특수·패링)의 구별 가능한 예고, 실제 공격 시점의 위치·방어 판정.
- 저스트 회피의 몬스터 슬로우, 패링의 그로기·어지러움 표시, 반격 가능 시간의 수동 공격 보너스.
- 판정·경감·상태 지속시간·배율의 DataSet 로딩/검증, 이후 스킬·스탯 보정의 경계.
- 기존 네이티브 공격/HitEvent·HP 단일 적용·피격/사망 연출 보존, 팝업 정지·중단·시간 경계 회귀와 CombatFoundation-F07.

제외:
- 3단계 승패·정산·경험치/Level·EXP, 10 Stage Run·방 전환·성장/저장·추가 몬스터/스킬 콘텐츠.
- 몬스터 점프의 기본 JumpDuration/JumpHeight 및 거리별 속도 정책 튜닝. 이는 [MonsterCombat](MonsterCombat.md)의 6단계 범위다.
- 다중 상대 전투·범용 몬스터 집합/광역 대상 관리·전면 리팩토링·새 핫바·다섯 번째 버튼·별도 반격 공격/모션·플레이어 이동 수치 변경.
- 배포·Maker 재시작·새 맵 생성·성능 개선 주장. 기존 후속 ID는 별도 승인·환경을 따른다.

## 4. 사용자 확정 규칙

2026-10-20 사용자 Q1~Q4의 A 선택과 Q5 직접 답변을 반영했다. D01~D04는 모두 확정됐으며 폐기한 선택안은 유지하지 않는다. 단위는 초, 배율은 원래 값에 곱한다.

### D01 — 공격 속성과 대응

- 일반: 예고된 방향 회피 또는 가드 홀드가 기본 대응이다. 방향 회피는 실제 범위를 벗어나면 피해 0, 가드는 D02 경감이다. 적절한 방향 저스트 회피는 슬로우 성공으로 인정한다. 일반 공격의 짧은 가드는 경감만 하고 패링 그로기는 발생시키지 않는다.
- 특수: 가드·패링 불가. 예고 방향으로 피격 범위를 벗어나야 한다. 적절한 방향 저스트 회피는 슬로우 성공이다. 특수+가드 대응 조합은 데이터 오류로 거부한다.
- 패링: 예고 방향의 저스트 회피 또는 정확한 ↓ 입력으로 피해 0·대응 성공. ↓ 성공은 그로기, 방향 성공은 슬로우다. 늦거나 이른 가드 홀드는 D02 경감, 범위 안의 회피 실패는 원래 피해다. 가드형 예고라면 패링만 저스트 성공으로 인정한다.

대응 유형(2026-11-03 사용자 결정으로 방향 무관 회피형 추가, 상세 §15):
- 뒤 회피형(LEFT)·앞 회피형(RIGHT): 2칸 영역. 예고 방향으로 벗어나면 피해 0, 그 방향 저스트 회피가 슬로우 성공이다.
- 방향 무관 회피형(설계안 이름 ANY): 예고 시작 순간 플레이어와 가장 가까운 BattlePos 1칸을 고정해 공격하며 이후 추적하지 않는다. 그 칸을 벗어나면 피해 0, 고정 칸에서 멀어지는 방향이면 어느 쪽이든 저스트 회피 성공이다. 끝 칸(Pos1·Pos3)은 벽 때문에 중앙 쪽 한 방향만 가능하다. 속성은 일반·특수·패링 모두 허용하며 위 속성 규칙을 그대로 따른다.
- 가드형(GUARD): 3칸 전체 영역. 유형·규칙·코드는 여러 칸을 치는 이후 보스용으로 유지하지만 주황버섯 데이터에서는 쓰지 않는다.

예고 유형은 기본 대응 방향, 속성은 가드/패링 허용 규칙이다. 실제 범위 밖의 플레이어에게 “틀린 버튼”을 이유로 피해를 만들지 않는다. 성공 보상은 해당 공격·예고에 맞는 입력에만 준다. 히트박스도 예고한 대응으로 피할 수 있도록 확인하며 무작위 목표만 바꾸고 예고를 붙이는 것으로 끝내지 않는다.

### D02 — 타이밍·피해

저스트 회피·패링의 유효 시작 구간은 실제 공격 시점 직전 **0.20초**, 일반 가드 피해는 **원래 피해 ×0.40(60% 경감)**, 유효한 저스트/패링 성공 피해는 **0**이다.

판정 시각 t에서 수락 시각 s가 t-0.20 ≤ s ≤ t면 타이밍 성공이다. 회피 방향은 수락된 MOVE 방향이며 같은 홀드의 추가 출처·복귀는 새 시작 시각을 만들지 않는다. 회피 입력을 먼저 뗐더라도 구간 안의 유효한 시작은 유지한다(현행 정책). 가드는 판정 순간 실제 홀드 중이어야 패링을 인정한다. t 이후 입력은 이전 공격을 뒤집지 않는다. 피해는 기본 피해·경감/보너스를 합성한 뒤 정수 내림하며 음수는 0으로 제한한다.

### D03 — 반격 보너스 대상·소비

모든 유효한 저스트 회피·패링 성공에 부여한다. 성공 후 전투 시간 **2.0초**, **다음 수락된 직접 공격 1회 전체 타격 ×2.2**다. ATTACK 진입과 유효한 시전 시작이 모두 성공한 시점에 소비하고 빗나가도 소비한다. 거부된 입력·시전 실패는 소비하지 않는다. 이미 실행 중인 공격에는 소급 적용하지 않는다.

공격 대상은 유일한 현재 대결 상대 1개체다. 기본 공격의 원래 사거리·타수를 유지하고 다른 몬스터를 추가 공격하지 않는다. 재성공은 중첩 없이 배율을 유지하고 2.0초를 갱신하며 만료 경계는 시작 ≤ 현재 < 종료다. 팝업 중 시간·소비는 멈추고 사망·맵 이탈·Stop에는 소멸한다.

### D04 — 1:1 상대·슬로우·그로기

사용자는 “전투하는 몬스터. 애초에 상대 몬스터는 1개체 고정(1:1대결)”이라고 명확히 했다. 전투는 **플레이어 1명과 현재 상대 몬스터 1개체**의 대결이며, 슬로우·그로기·직접 공격 모두 그 상대를 대상으로 한다. 같은 맵의 몬스터 전체를 모으는 구조는 만들지 않는다.

저스트 회피 성공 시 그 상대의 행동 진행을 **2.0초 동안 ×0.5**로 늦춘다. 공격/접근·복귀·다음 행동 대기·예고와 그에 맞는 모션 재생을 함께 늦추고 플레이어·팝업/토스트·오디오는 늦추지 않는다. 패링은 그 상대를 **1.5초 그로기**로 만들고 어지러움 표시를 낸다. 패링 성공 시 그 공격의 미실행 타격을 취소하고, 처음 위치(Home)로 복귀를 마친 뒤 그로기를 시작한다. 그로기 종료 후에는 기존 대기로 돌아간다(**2026-11-02 사용자 변경**, V11-F02). 복귀는 기존 공격 복귀와 같은 적 행동 진행·슬로우·피격 규칙을 따른다. 반격 창 2.0초는 기존대로 패링 성공 시점부터 잰다. 따라서 복귀 시간만큼 반격 창 안의 그로기 구간이 줄어들며, 사용자는 이를 안내받고 선택했다. 수치는 바뀌지 않는다.

슬로우·그로기 지속시간은 적의 느려진 시간과 별개인 정지 가능한 맵 전투 시간으로 잰다. 동일 효과는 중첩 없이 남은 시간을 새 전체 지속시간으로 갱신한다. 둘이 겹치면 그로기가 행동을 막고 슬로우의 남은 지속시간은 흐른다. 팝업 중 둘 다 만료되지 않으며 사망·이탈·Stop 또는 상대 참조 폐기 시 제거한다. 비전투 몬스터·다른 플레이어의 상대는 대상이 아니다. 그로기 중 맞으면 피해는 받을 수 있으나 HIT 모션이 그로기를 조기 해제하지 않게 한다.

현재 파일을 우선 확장한다. 신규 컴포넌트가 필요하면 Combat/·UI/ 등 기존 기능 폴더에 두고 모델/맵/UI 연결은 해당 빌더로만 수정한다. 실제 구조·API는 coder 사전 점검에서 확인한다. 현재 맵은 MapleTile(0)·Rigidbody이며 1단계 이동과 Body 설정을 바꾸지 않는다.

UserDataSet 메타데이터와 동명 UTF-8 CSV가 실제 적용되도록 연결한다. 문자열을 수치로 검증하고 누락·중복 ID·빈 문자열·NaN/무한대·음수 시간·0 이하/1 초과 슬로우·잘못된 유형 조합은 시작을 거부해 한 번 경고한다. 성공/피해 정책을 임의 기본값으로 바꿔 진행하지 않는다. 서버가 유효 행의 스냅샷을 소유하고 클라이언트는 승인된 표시 값만 받는다. 캐시는 세션 종료에 정리하며 Refresh/다음 Play에서 변경값이 적용돼야 한다.

반격 대상/소비 정책과 상태 대상은 D03/D04 고정 규칙으로 검증한다. 대상 범위를 다중 몬스터로 바꾸는 설정은 추가하지 않는다.

스킬·스탯 보정은 base settings → modifier → 유효 범위 검증 → 실행 스냅샷 경계만 둔다. 현재 보정은 항등값이며 새 레벨·장비·저장·성장 공식은 추가하지 않는다. modifier의 무효 값도 새 동작 거부로 처리한다. 기존 UserDataSet/CSV 편집 정책과 Maker 등록 절차는 구현 시 관련 참조를 따른다.

### 판정·시간 순서

1. 공격 수락 시 예고·유형/속성·히트박스·실행 ID를 고정하고 대상 클라이언트에 같은 예고를 보낸다.
2. 실제 공격 시점에 서버가 현재 대결 쌍의 플레이어 위치/홀드·수락 시각과 해당 실행 정보를 한 번 읽는다. 네이티브 콜라이더 판정과 결합해 방어·저스트 결과를 확정한다. 범위 밖 성공은 CalcDamage 콜백에 의존하지 않는다.
3. 결과는 공격 실행 ID·플레이어 ID로 중복 적용을 막고, 허용된 경우 슬로우/그로기·반격 권한·피드백을 한 번 전달한다. UI는 표시만 하며 피해를 다시 계산하지 않는다.
4. 실제 피격 후보의 CalcDamage/HitEvent는 확정한 최종 정수 피해를 사용한다. 회피·패링 0, 가드·일반·치명 피해의 숫자/HP가 일치하고 네이티브 HP 단일 소유를 유지한다.
5. 수동 공격은 수락·시전 성공 시 현재 권한을 고정해 원래 타수의 피해에 적용한다. 소비·만료·중단 뒤 늦은 콜백으로 권한을 복구하지 않는다.

슬로우는 전역 SetClientTimeScale을 낮추지 않는다. 이것은 팝업 정지가 이미 소유하며 플레이어/UI까지 영향을 준다. 맵 전투 시계의 delta를 현재 상대의 행동 진행으로 적분해 갑작스러운 배율 변경 때 위치나 예약이 점프하지 않게 한다. 슬로우 적용 전 진행분은 보존하고 모션과 실제 공격 예약이 같은 적 행동 진행을 읽는다. 배율을 끌 때에도 기준 진행량을 보존한다. 그로기/효과 자체의 만료·반격 창은 맵 전투 시간을 따른다. 그로기 1.5초는 패링 뒤 복귀를 완료한 시점부터 잰다(2026-11-02 사용자 변경).

중단 우선순위는 사망·맵 이탈·Stop/엔티티 제거 → 실행 무효화 → 팝업 정지 → 그로기 → 슬로우 → 정상 동작이다. 팝업은 실행을 취소하지 않고 남은 시간을 보존한다. 단, 닫기에서 이전 가드·회피 시각은 0단계 계약대로 폐기하고 중앙 복귀한다. 패링 성공은 해당 몬스터의 미실행 타격을 취소하고 처음 위치 복귀를 완료한 뒤 그로기에 진입한다. 취소한 타격은 그로기 종료 후 재개하지 않는다. 복귀 중 팝업은 복귀 진행을 보존하고, 사망·이탈·Stop·상대 참조 폐기는 그로기 진입보다 우선한다(2026-11-02 사용자 변경). 사망/이탈 뒤 상태·위치·효과·UI를 되살리는 늦은 완료를 거부한다.

현재 대결 상대 참조는 기존 전투/MonsterManager의 참조를 확인해 단일 소유자에 둔다. coder는 기존 참조와 수명 경계를 확인해 한 곳만 갱신하며 각 공격·상태·UI가 같은 상대를 읽게 한다. 참조가 없거나 유효하지 않으면 동작을 거부하고, 사망·이탈·상대 교체 시 이전 실행/효과를 무효화한다. 동일 맵이라는 이유만으로 임의의 몬스터를 선택하거나 타깃 집합을 순회하지 않는다. 다른 접속자의 진행과 효과를 격리할 수 없으면 범위를 확장하지 말고 차단 사유를 보고한다. Run/방 생성·다중 몬스터 탐색/선택 체계는 선행 구현하지 않는다.

3. 1칸 공격을 추가한다. 사용자 원문: "그런 공격도 있어야됨. 안그럼 난이도가 너무 올라", "일반 몬스터들도 필요하니까 1위치 공격은 필수야." 선택 화면 결정: 예고 시작 순간 플레이어와 가장 가까운 칸을 고정하고 이후 추적하지 않는다. 범위를 벗어나는 방향이면 어느 쪽이든 저스트 회피 성공(슬로우·반격 보너스)이다. 일반·특수·패링 속성을 모두 허용한다.
4. 출현 비율은 DataSet 가중치 열로 정하며 기본값은 모두 1이다.
5. 몬스터 수치(HP·공격력·공격 간격·점프 시간/높이) DataSet화는 이번 범위가 아니다. V11 종료 뒤 별도 승인 회차에서 다룬다(아래 V11-F07).

### 역할 분리 (2026-11-03 사용자 추가 지시)

사용자 원문: "추가로 2칸공격 위치는 일단 주황버섯에 한정된 얘기임. 다른 보스(ex: 잨쿰)는 2칸 공격에 2개의 이펙트 공격이 나올 수 있음.(2개의 팔 공격 이펙트). 이부분을 염두하고 세팅해줘."

- 패턴 데이터는 어느 칸을 맞히는지(영역), 대응 유형·속성·예고·가중치만 정한다. 그 영역을 어떤 모션·이펙트로 실현할지는 몬스터별 공격 구현이 정한다. 주황버섯은 점프 1회로 영역 중앙에 착지한다. 이후 보스는 맞는 칸마다 이펙트·타격을 따로 둘 수 있다(예: 자쿰 2칸 = 팔 2개).
- "착지점 = 영역 중앙"을 공통 로더(CombatRuleCatalog)와 MonsterAttackComponent의 공통 규칙으로 넣지 않는다. 주황버섯 공격 모션(OrangeMushroomAttack)의 동작으로 둔다.
- MonsterAttackComponent는 실행마다 고정한 영역을 칸 집합(현재 TelegraphCells와 같은 1~3칸 정보)과 월드 x 범위(min~max)로 모션 담당에 넘긴다. 몬스터별 모션이 칸별 이펙트·타격을 붙일 수 있는 확장 지점만 남긴다.
- 지금 영역은 From~To 연속 범위다. 떨어진 칸 조합(예: Pos1+Pos3)과 칸별 다중 타격 같은 보스 전용 형식은 구현하지 않는다. 이 형식은 보스 공격 계획에서 결정한다(후속, ID 없음).

| 대응 유형 | 영역 | 피해 0 조건 | 저스트 회피 유효 방향 | 가드·패링 | 주황버섯 데이터 |
| --- | --- | --- | --- | --- | --- |

| RIGHT 앞 회피형 | Pos1~Pos2 | 영역 밖(Pos3) | RIGHT | D01 속성 규칙 | 사용 |

| GUARD 가드형 | Pos1~Pos3 | 없음 | 없음(패링 속성의 ↓ 패링만 성공) | D01 속성 규칙 | 제외(보스용 유지) |

ANY 세부 규칙:
- 대상 고정: PrepareAttack(예고 시작) 시점의 플레이어 엔티티 WorldPosition.x와 BattlePos1~3의 x를 비교해 가장 가까운 칸 하나를 실행 스냅샷에 고정한다. 동률은 결정적 규칙(같은 입력이면 같은 칸)으로 coder가 정해 WorkRecord에 남긴다. 영역은 그 칸 x ± AreaPaddingX이고, 유효 저스트 방향 집합도 같은 스냅샷에 고정한다. 슬로우·팝업으로 예고가 늘어나도 다시 조준하지 않는다.
- 탈출 검증: 유효 방향의 도착 위치(Pos2 조준이면 Pos1·Pos3, 끝 칸 조준이면 Pos2)에 선 플레이어 콜라이더가 영역을 완전히 벗어나는지 기존 LEFT/RIGHT 검증과 같은 방식으로 확인한다. 실패하면 그 공격을 시작하지 않고 1회 경고한다.
- 끝 칸: Pos1·Pos3 조준은 벽 때문에 중앙 쪽 한 방향만 가능하다. 기존 입력 규칙(1단계·D02)은 바꾸지 않는다. 끝 칸에 선 플레이어는 그 방향을 홀드 중이므로 새 회피를 시작할 수 없고, 홀드를 떼 중앙 복귀로 벗어난다. 복귀는 새 회피 시작 시각을 만들지 않으므로 이 경우 저스트 보상은 없고, 판정 순간 영역 밖이면 피해 0이다. 끝 칸 조준이라도 플레이어가 예고 중 중앙에 돌아와 있으면 중앙 쪽 방향 회피를 창 안에 시작해 저스트를 얻을 수 있다.
- 방어 판정: 가드 분기는 기존과 같다. 회피 분기는 ANY일 때 수락된 MOVE 방향이 스냅샷의 유효 방향 집합에 있고 0.20초 창 안이면 저스트다. 범위 밖 저스트도 한 번만 판정한다. 범위 밖이면 버튼과 무관하게 피해 0이다(D01).
- 표시: F01 빨강 칸은 고정한 1칸만 켠다. 예고 문구는 방향 무관 회피임을 나타낸다(예: "일반 · 회피 [좌·우] / 가드"). 구체 표현과 색은 coder가 기존 예고 문구 범위에서 정한다. 현재 예고는 문구·색으로만 구별하고 아이콘 요소가 없으므로 .ui는 바꾸지 않는다. 아이콘 등 .ui 요소가 필요하다고 판단되면 구현하지 말고 근거를 기록해 반환한다.

### 주황버섯 패턴 데이터 (설계안, 9행)

modelId(castleenemy)·AreaPaddingX 0.5·AreaHeight 1·AreaOffsetY 0.4·TelegraphLeadSec 0.5는 기존 행 값을 그대로 쓴다. 모든 행 Weight=1이므로 각 행 출현 확률은 1/9다.

| id | ResponseType | AttackAttribute | AreaFromAnchor | AreaToAnchor | Weight | 주황버섯 착지(모션이 영역에서 도출) |
| --- | --- | --- | --- | --- | --- | --- |
| normal.left / special.left / parry.left | LEFT | NORMAL / SPECIAL / PARRY | 2 | 3 | 1 | Pos2·Pos3 중간 |
| normal.right / special.right / parry.right | RIGHT | NORMAL / SPECIAL / PARRY | 1 | 2 | 1 | Pos1·Pos2 중간 |
| normal.any / special.any / parry.any | ANY | NORMAL / SPECIAL / PARRY | 0 | 0 | 1 | 고정 칸 |

- 제거: normal.guard·parry.guard.
- ANY 영역 표현(설계안): AreaFromAnchor=AreaToAnchor=0을 "예고 시작 시 플레이어 조준 1칸"으로 쓴다. 로더는 ANY에서만 0/0을 허용하고, 다른 유형의 0이나 ANY의 0 아닌 값은 거부한다. coder가 더 명확한 동등 표현을 택하면 모호한 값을 거부하는 같은 검증을 두고 WorkRecord에 기록한다.
- LandingAnchor 열: 착지점을 더 이상 데이터로 정하지 않는다. 열 제거(로더 필수 열에서도 제거)와 무시(값이 모션에 영향 없음) 중 coder가 안전한 쪽을 정해 기록한다. 어느 쪽이든 모션과 판정이 데이터로 어긋나지 않아야 한다.
- 주황버섯 착지: OrangeMushroomAttack이 넘겨받은 영역의 월드 x 중앙((min+max)/2)으로 점프한다. 2칸은 두 칸의 중간, 1칸은 그 칸 위치다. 점프 시간은 거리와 무관하게 0.5초 고정이므로 판정 시각은 바뀌지 않는다. 판정 박스의 x는 지금처럼 영역에서 정하고 y는 몬스터 위치+AreaOffsetY를 유지한다.

### 가중치 선택 (Weight)

- 열 이름은 Weight(설계안)이다. 값은 유한한 양수만 허용한다. 열 누락·빈 값·숫자 아님·0·음수·NaN/무한대는 기존 데이터 정책대로 카탈로그 전체 시작을 거부하고 1회 경고한다. 부분 행이나 기본값 대체로 진행하지 않는다. 패턴을 끄려면 행을 지운다(0을 비활성으로 쓰지 않는다).
- 선택: 같은 modelId 행의 가중치 합 W에 대해 r = math.random() × W를 뽑고, CSV 행 순서로 누적해 r < 누적합인 첫 행을 고른다. 부동소수 오차로 끝까지 고르지 못하면 마지막 행을 쓴다. 기본 1이면 기존 균등 선택과 같은 분포다.

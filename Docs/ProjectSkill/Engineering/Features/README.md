# Features — 이 프로젝트의 결과물 개발문서

현재 기능을 이해·사용·조절하는 설명서다. 팀 책임·승인·완료 절차는 [ChatRoles 운영 규칙](../../ChatRoles/README.md)을 따른다. 앞으로 할 일은 [Plans](../Plans/README.md), 상세 작업은 [WorkRecords](../WorkRecords/README.md)로 구분한다.

## 파일명·작성 시점

- 로드맵 단계: {단계번호}_{FeatureKey}.md. 제목에도 단계를 표시한다.
- 독립 완성 기능: {FeatureKey}.md. 단발 진단·잔여 확인은 Plans/WorkRecords로 관리한다.
- 기능 또는 승인된 작업 단위가 완료되면 작성한다. 번호가 있다고 단계 전체 완료를 뜻하지 않는다. 부분 완료·미확인은 본문에 표시한다.

## 내용·편집 책임

- 개발: 현재 기능·사용/조절 방법·최소 구조·제약.
- tester: 확인한 주체·환경·대상 버전·짧은 결과와 남은 확인.
- reviewer: 요구·실제 변경·테스트의 일치 여부와 결과 표현의 한계 검토. 코드·QA 판정은 변경하지 않음.
- 기획: 실제 사용자 결정·선택·직접 플레이 피드백.
- 본문은 대략 1~2화면을 목표로 하고 사용에 필요한 조건은 생략하지 않는다. 전체 코드·콘솔·소스 지문·AI 시행착오를 누적하지 않는다.
- 사용자 요구/선택과 AI 구현/검증을 구분한다. 선택 이유·평가를 추정하거나 AI 기술 해결을 사용자 성과로 쓰지 않는다.
- 같은 내용을 복사한 별도 개발문서를 만들지 않는다. 현재 결과를 갱신하되 과거 확인을 새 버전의 신규 실행으로 바꾸지 않는다.

## 기본 틀

```markdown
# {단계번호}단계 — {FeatureKey} — {기능}

## 현재 결과
{완료 범위·날짜·한계}

## 사용·조절 방법
{조작·설정·최소 파일/흐름·주의}

## 본인 결정·플레이 피드백
{실제 확인된 사용자 요구/선택/직접 평가}

## 반영 결과·확인 범위
{확인 주체·환경·짧은 결과·ID·미확인 추적 링크}

## 역할
{사용자 / AI / 엔진·외부 자료}
```

실제 공개용 영상·캡처를 확보한 경우 Assets/{FeatureKey}/에 보관한다. 원시 JSON은 기본 생성하지 않는다. [포트폴리오 초안](../../../../Portfolio/Portfolio.md)은 별도 산출물이며 요청받아 제작할 때만 [바이브 코딩 포트폴리오 제작 원칙](../../Vibe_Coding_Portfolio_Guide.md)을 적용한다. 이 개발문서 자체가 포트폴리오 원고는 아니다.

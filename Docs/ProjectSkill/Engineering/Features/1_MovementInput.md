# 1단계 — MovementInput — 앞뒤 이동·입력

## 현재 결과

2026-10-20 사용자 보고 **“v08 확인완료. 다음 단계 진행해줘.”**를 반영해 1단계를 완료했다. 근거는 2026-10-19의 구현·낙하 수정 AI Maker 확인과 사용자의 MovementInput-V08 확인 완료 보고다. 다음 단계는 [2단계 전투 핵심 계획](../Plans/2_CombatCore.md)이다.

## 사용·조절 방법

- ←/A 또는 왼쪽 버튼은 뒤로, →/D 또는 오른쪽 버튼은 앞으로 이동한다.
- 홀드하면 해당 지점에서 대기한다. 마지막 출처를 해제하면 이동 중이더라도 그 자리에서 중앙 복귀한다.
- 중앙 복귀가 끝나기 전 공격·가드·새 방향 입력은 무시한다. 입력 예약은 없으며 이후 다시 입력해야 한다.
- 팝업 중 이동은 멈추고 닫은 뒤 중앙으로 복귀한다. 사망·상태 이탈·맵 이탈·종료 시 이전 이동을 폐기한다.
- [PlayerMoveComponent](../../../../RootDesk/MyDesk/Player/PlayerMoveComponent.mlua)의 MoveSpeed·ReturnSpeed는 각각 6이다. V08 확인 당시의 현행값이며 별도 DataSet 연결은 없다. 사용자가 숫자 6을 별도로 확정했다는 의미는 아니다.
- 목표는 맵의 BattlePos1/2/3 참조다. 현재 X=-1.5/0/1.5이며 위치 변경은 맵 편집으로 한다.

입력 수락은 PlayerStateControl, 이동은 PlayerMoveComponent, 상태 진입/이탈은 Player_Move가 맡는다. 소유 클라이언트 Rigidbody의 수평 이동을 사용하며 공중 Y·중력은 강제로 고정하지 않는다. 이동이 바꾼 물리 설정은 끝날 때 복원한다.

## 본인 결정·플레이 피드백

본인은 이동·입력 단계 개발을 요청했고 실제 플레이 중 이동 시 낙하를 발견해 수정을 요청했다. 2026-10-20 V08 확인 완료와 다음 단계 진행을 직접 알렸다. 이를 수정 후 현재 이동·입력 단계의 사용자 수락으로 반영했다. PC·모바일별 관찰 내역, 기기명, 개별 화면·터치 평가나 숫자별 체감 평가는 답변에 없으므로 덧붙이지 않는다.

원인 분석·네이티브 이동으로의 변경·자동 재검증은 AI 수행이다.

실제 다른 맵 전환은 [CombatFoundation-F03](../Plans/CombatFoundation.md)·[CombatPause-F01](../Plans/CombatPause.md), 기기 전반의 UI·음향·몬스터 사망 연출은 [CombatFoundation-F04](../Plans/CombatFoundation.md)·[CombatPause-F02](../Plans/CombatPause.md)에 남는다.

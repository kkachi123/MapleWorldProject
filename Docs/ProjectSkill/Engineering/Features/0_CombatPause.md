# 0단계 — CombatPause — 팝업 중 전투 일시정지

## 현재 결과

2026-10-18 현재 map01의 구현·AI Maker 자동 검증을 마쳤다. 사용자 승인으로 실제 다른 맵 전환·PC/모바일 화면·음향은 [후속 확인](../Plans/CombatPause.md)으로 남겼다. 모든 기기의 확인 완료가 아니다.

## 사용·조절 방법

- UIPopup을 열면 요청 대기부터 새 전투 입력을 막고 서버 승인 후 팝업을 표시한다.
- 전투 이동·피해·AI·예약·판정 시간은 멈춘다. 팝업·토스트는 계속 갱신한다.
- 닫으면 공격은 남은 실행부터 재개한다. 가드·회피 홀드는 비우고 회피는 중앙 복귀한다. 정지 중 입력을 다시 실행하지 않는다.
- 사망·이탈·종료는 재개보다 우선한다. BGM·효과음은 정지하지 않는 코드 정책이며 실제 청취 확인은 남아 있다.

[CombatPauseComponent](../../../../RootDesk/MyDesk/Combat/CombatPauseComponent.mlua)가 맵의 전투 시계·정지 상태를 관리한다. 공격·몬스터 모션은 전투 시계를, [UIPopup](../../../../RootDesk/MyDesk/UIPopup.mlua)·[UIToast](../../../../RootDesk/MyDesk/UIToast.mlua)는 실시간을 사용한다. 서버는 요청자·현재 맵·세션과 해당 맵 사용자 1명 조건을 확인한다. 이는 여러 사용자의 Run 격리 시스템 완성을 뜻하지 않는다.

새 전투 기능은 같은 전투 시계와 사망/종료 우선순위에 연결해야 한다. 별도 사용자 조절 수치는 이번 결과에 추가하지 않았다.

## 본인 결정·플레이 피드백

본인은 기획·제작 진행을 승인하고 실제 맵 전환·화면·음향을 후속으로 분리하는 선택을 했다. 해당 환경의 직접 확인 결과는 아직 없다. 시계 분리·사망 상태 처리·종료 응답 수정은 AI 작업이며 본인 기술 성과로 소개하지 않는다.

초기 사망 전환 실패와 종료 수신자 오류는 AI가 수정했다. 최종 R03 런타임 Error/Warning 0, 빌드 40건 모두 Info라는 기존 결과를 요약한다. 실패 회차를 모두 통과한 것으로 바꾸지 않는다. 공격 간격의 프레임 오차·die 가시성·음향·실제 맵 전환·CPU/메모리 성능은 입증하지 않았다.

이번 문서 정리에서 새 Play는 하지 않았다. 상세 회차 JSON·소스 지문 6개는 2026-10-19 문서 구조 정리로 삭제해 현재는 요약만 남는다. 공개용 영상·캡처는 아직 없다.

# WorkRecords — 이 프로젝트의 임시 작업 기록

개발·QA·리뷰의 실행 내역과 이어하기 정보를 보관한다. 팀의 인계·권한·공유 파일/Maker 사용 규칙은 [ChatRoles 운영 규칙](../../ChatRoles/README.md)을 따른다. 계획서 작성 원칙과 작업 기록 양식은 분리한다.

## 위치·편집

- 파일명: {FeatureKey}WorkRecord.md. 같은 작업의 개발·QA 기록은 한 파일을 순차 사용한다.
- coder는 개발 절, tester는 QA 절, reviewer는 리뷰 절, 메인 조율 채팅은 감독·인계 절을 갱신한다. 다른 역할의 진행 중 편집을 덮어쓰지 않는다.
- 목표·승인 범위·완료 기준은 [Plans](../Plans/README.md), 현재 결과는 [Features](../Features/README.md)에 둔다.
- 기록은 재개에 필요한 상세 정보만 남긴다. 전체 채팅·콘솔·해시의 자동 보관소나 사용자 포트폴리오 원고가 아니다.

실행별 [.pipeline run](../../../../.pipeline/README.md)은 이 기록의 각 절을 링크하고 상태만 관리한다. 개발·QA·리뷰 전문을 run에 중복 작성하지 않는다. 기존 기록은 그대로 유지하고 새 실행의 독립 검사와 구분한다.

## 작성 틀

```markdown
# {FeatureKey} — 임시 작업 기록

- 연결 Plan:
- 상태·갱신일:
- 삭제 조건: {해당 범위 완료·필요 결과/미완료 추적 이관·링크 정리}

## 현재 재개 지점
{마지막 상태·다음 행동·남은 차단 조건}

## 역할 간 인계
- 인계일·다음 담당·사용자가 승인한 범위:
- 대상 Plan/요구 ID·변경 파일/버전:
- 이미 확인한 조건·미확인:
- 다음 행동:
- Maker 최종 관찰 모드·담당·사용 종료 여부:

## 감독·인계 기록
{확인 시점·담당 채팅/역할·사용자 승인 범위·전달 여부·최근 결과·다음 담당}

## 개발 기록
{날짜·실제 변경·실패·폐기한 시도·기본 검증·남은 문제}

## QA 기록
{ID·주체·버전·맵/공간·초기 조건·순서/횟수·기대/실제·근거·판정·영향·재검증}

## 리뷰 기록
{검토 버전·요구/결함 ID·READY/CHANGES_REQUIRED/WAITING/STOP·근거·다음 담당·사용자 판단}

## 완료 시 이관할 내용
{Features의 짧은 결과, Plans의 미완료 추적, 실제 사용자 피드백}
```

Maker 담당 기록은 자동 잠금 장치가 아니다. 과거 모드를 현재 사용권/접속 상태로 간주하지 않는다. PASS / FAIL / 미실시 / 기획 확인 필요를 구분하고 기존 실패를 덮어쓰지 않는다.

## 수명

작업 중 필요한 실패·검증·버전·다음 행동은 유지한다. 사용자 확인 등 전체 작업 범위가 남으면 삭제하지 않는다. 완료 후 현재 동작·사용자 피드백·짧은 결과만 Features에 반영하고, 미완료 항목은 유지할 Plans에 연결한다. 링크를 정리한 뒤 임시 파일을 삭제한다. 상세 원장을 Features에 복사해 영구 보존하지 않는다. README는 운영 지침으로 유지하며 공개용 시연 자료는 별도로 보관한다.

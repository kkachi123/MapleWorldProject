# Project StayCool — AI 활용 게임 제작 포트폴리오 초안

> 작성: 2026-10-19. 최종 제출본이 아니다. 본인이 대화에서 확정한 요구·선택·직접 관찰과 AI 작업을 구분한다. 기획된 기능을 완성된 기능으로 소개하지 않는다.

## 제작 목표와 방식

4방향 대응 전투와 방 카드 탐험을 결합한 1인 로그라이트를 MSW로 제작 중이다. 본인은 기획·요구사항 구체화·제안 선택·직접 플레이 피드백을 담당하고, AI가 코드 작성·진단·자동 검증·문서화를 수행한다. 모든 기존 코드의 줄별 작성 이력은 확보하지 않았다.

상세 목표는 [게임 기획](../Docs/ProjectSkill/Engineering/GameDesign.md), 개발 순서는 [로드맵](../Docs/ProjectSkill/Engineering/DevelopmentRoadmap.md)을 따른다.

## 본인이 확정한 제작 방향

| 주제 | 확인된 요구·선택 | 현재 상태 |
| --- | --- | --- |
| 플레이 환경·UI | PC·모바일 가로 화면 공통, 하단 십자형 입력, 방 카드 3장 중 선택안 채택 | 기획 확정. 실제 기기·최종 UI 확인은 남음 |
| 공격 규칙 | 공격은 기존 공격 입력만 사용. 저스트/패링 성공은 자동 공격이 아닌 후속 공격 피해 증가 | 기획 확정·2단계 개발 대상. 현 프로토타입에는 자동 반격이 남음 |
| 판정 확장 | 저스트/패링 수치를 DataSet에서 조절하고 이후 스킬·스탯 보정 기반 마련 요구 | 기획 확정·미구현 |
| Run·정산 | 1인 전용, 상점은 보스 전 고정, 임시 요소는 한 판 종료/사망 때 소멸, 경험치는 전투 종료 후 정산 | 기획 확정·후속 단계 대상 |

사용자가 직접 밝히지 않은 선택 이유나 효과는 덧붙이지 않는다. 위 항목은 기획 참여 근거이며 완성 성과 목록이 아니다.

## 직접 플레이 피드백과 반영

- 본인은 주황버섯 점프가 빠르고 공격 위치에서 피해가 없는 것 같다고 보고했다. AI가 현재 설정·판정 조건을 진단했다. 본인은 속도 조절을 이후 몬스터 제작 시 검토하도록 요청했다. [후속 검토·설정 안내](../Docs/ProjectSkill/Engineering/Plans/MonsterCombat.md).
- 본인은 이동 중 낙하를 발견하고 수정을 요청했다. AI가 재현·코드 수정·Maker 반복 검증을 수행했다. 수정 후 본인의 최종 체감·화면·터치 확인은 아직 대기다. [현재 이동](../Docs/ProjectSkill/Engineering/Features/1_MovementInput.md).

이 기록은 플레이 관찰·수정 요구의 사례다. 원인 분석이나 기술 해결을 본인의 성과로 표현하지 않는다. 아직 충분한 전후 시연·최종 평가가 없어 발표용 대표 사례 선정은 보류한다.

## 현재 결과와 한계

전투 프로토타입 안정화·팝업 정지·이동 구현의 현재 설명은 [개발문서](../Docs/ProjectSkill/Engineering/Features/README.md)에서 관리한다. AI의 현재 맵 자동 검증과 본인의 실제 플레이 확인을 구분한다. 전체 Run·성장/저장·콘텐츠·실기기/배포 검증은 완료되지 않았다.

공개용 영상·캡처, 확정된 개발 기간, 성능 비교 수치는 아직 기재할 근거가 없다. 확보 후 추가한다. AI의 임시 작업 기록·긴 코드·회귀 원장은 포트폴리오 본문에 넣지 않는다.

## 이후 보완할 자료

- 본인의 수정 후 플레이 평가와 실제로 조정한 내용.
- 기획 의도와 결과를 비교할 수 있는 짧은 실제 시연.
- 각 사례에서 본인이 결정한 범위와 AI가 구현한 범위.
- 실제 발표 목적에 맞춘 사례 선정·분량. AI 기술 문제 해결 대본은 작성하지 않음.
